# k3s node configuration (not Argo-managed)

Files here are applied on the node, not by Argo CD.

## Traefik resources

`traefik-resources.yaml` is a `HelmChartConfig` for the Traefik chart that k3s bundles. Copy it to the node's
k3s manifests directory (`/var/lib/rancher/k3s/server/manifests/`, e.g. as `traefik-resources.yaml`). k3s' helm-controller
applies it and merges its values over the packaged chart values; it survives k3s upgrades. Never edit the packaged
`traefik.yaml` there (k3s overwrites it). Applying it redeploys Traefik (single replica: a few seconds of ingress downtime).
Rollback: delete the file from the manifests directory and delete the `HelmChartConfig` (`kubectl -n kube-system delete helmchartconfig traefik`).

## Bundled pods left without limits

metrics-server, local-path-provisioner and the servicelb pods (`svclb-traefik`) have no requests or limits.
k3s offers no supported setting for them: their manifests under the manifests directory are rewritten on every k3s
start/upgrade, there is no `HelmChartConfig` for them (they are plain manifests, not Helm charts), and the servicelb
pods are generated by the k3s servicelb controller. Editing or patching them would be reverted, so they are left as they
are. They are small and bounded (tens of MB, near-zero CPU).

system-upgrade-controller is not bundled: see `k3s-upgrade/suc-resources-patch.yaml` and `k3s-upgrade/README.md`.
